Product Management Artifact

Product Requirement Document (PRD) & Scoring Methodology

1. Problem Statement & User Pain Point

Laptop buyers face severe cognitive overload. Raw specification sheets list 50+ cryptic acronyms (LPDDR5X-7467, PCIe Gen4x4, 140W TGP, ΔE < 1.5, MIL-STD-810H) without translating them into actionable utility for a specific buyer's workflow. Furthermore, static comparison sites lack real-time AI ingestion for newly launched models and treat a 2.8 kg gaming rig and a 1.1 kg enterprise ultrabook with the same yardstick.

2. Core Value Proposition

  • 25-Category Standardized Telemetry: Normalizes disparate hardware metrics onto an objective 0–100 scale.
  • LLM-Assisted Spec Ingestion: Uses Gemini structured JSON schemas to synthesize and score any laptop model on demand.
  • Cloud Firestore Persistence: Real-time `onSnapshot` synchronization for shared catalogs and comparison snapshots.

3. Product Success Metrics (North Star & KPIs)

  • Decision Confidence Rate: % of users who identify a clear winner and save a comparison snapshot within 90 seconds.
  • Long-Tail Catalog Coverage: % of user-searched models dynamically ingested via Gemini API and cached in Firestore.
  • Persona Engagement Rate: % of sessions interacting with the Persona Weighting Engine.

4. Mathematical Scoring Architecture

Overall Weighted Score (0–100) = Σ (Pillar_Score_i × Persona_Pillar_Weight_i) / Σ (Persona_Pillar_Weights)

Each of the 25 categories is scored from 0–100 and mapped to one of 5 core pillars: Compute & Graphics, Display & Media, Portability & Battery, Modularity & Connectivity, and Value, Security & Support.
